# Design Pillars

This page is the project’s “north star”. If you only read one thing before adding content, read this.

## What the Wiki is
- **Canon**: the Wiki defines the intended world + how systems should be described.
- **A contract**: pages can include *Design intent* and *Constraints* that future work should respect.

## How the game should evolve
- When adding a mechanic or content, update (or add) at least one Wiki page.
- Prefer making the game match canon pages, not the other way around.
- If we do need to change canon, record a retcon (don’t silently rewrite history).

## Lore-to-Game Hooks
**UI hooks**
- Use subtle links and “?” affordances to point to the Wiki.

**Asset hooks**
- Let lore drive asset needs: icons, backgrounds, sprites, and “vibe” references.

**System hooks**
- Wiki text drives presentation first (naming/voice/descriptions), and influences mechanics as they’re implemented.
